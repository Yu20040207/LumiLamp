# 唤醒后单舵机动作：USB CDC 设计

## 目标

在树莓派的 LumiLamp 语音循环检测到本地唤醒词并完成本地唤醒回应后，令
ESP32-S3 控制已验证的 ID 1 ST-3215-C018 执行一次低风险空载点头：相对
`+5°`、停 `0.5 s`、相对 `-5°`、关闭扭矩。

## 范围与前提

- 只新增树莓派端 USB CDC 串口适配器及其语音循环调用点。
- ESP32-S3 继续使用仓库中已有的 `firmware/esp32/sts3215_test` 固件协议；
  不修改 GPIO17/18、UART、供电、舵机 ID、总线波特率或 ESP32 固件。
- 运行时设备路径必须来自 `/dev/serial/by-id/`，当前实测候选为
  `usb-Espressif_USB_JTAG_serial_debug_unit_90:70:69:F7:F0:B0-if00`，但不把
  其具体序列号写死在源码或配置默认值中。
- 真实动作仅在用户确认：URT-2 为 3V3、舵机 12V 独立供电、空载且周边无干涉
  后进行。本次已获得该确认。
- 不新增自动烧录、ESP32 自动更新、全双工语音或多关节行为。

## 架构与数据流

`VoiceLoop` 只依赖一个异步的 `wake_motion()` 适配器，不直接打开串口。
在缓存的唤醒回应完成后、普通 ASR 开始前调用该适配器。适配器由一个独立
USB CDC 客户端实现，持有单一稳定设备路径和明确的逐命令超时。

```text
本地 KWS
  -> 本地唤醒回应播放完成
  -> WakeMotionAdapter
  -> /dev/serial/by-id/... (USB CDC)
  -> ESP32 安全测试固件
  -> URT-2 -> ID 1 舵机
```

## 命令序列与完成条件

一次 `wake_motion()` 严格按以下顺序执行：

1. 打开 USB CDC；清除本次会话前的输入。
2. 发送 `status`，在超时内要求有效 `position=... voltage=... temperature=...`
   遥测行。ESP32 自身继续负责 9–13V、低于 65℃和通信有效性判定。
3. 发送 `move 5`，要求 `OK: target=...`。
4. 等待 `0.5 s`。
5. 再发送 `status` 并要求有效遥测。
6. 发送 `move -5`，要求 `OK: target=...`。
7. 无论正常还是错误路径，都发送一次 `torque off`；正常结束要求
   `OK: torque disabled`。

这不是机械零位标定，也不保证回到原始编码器位置；它只是在现有相对运动
安全限制内完成一次小幅空载动作。

## 故障、超时与半双工规则

- 串口不存在、不能打开、超时、收到 `ERROR:`/`BLOCKED:`、格式不正确或状态
  不可信时，停止后续运动，尝试 `torque off`，向语音循环返回脱敏的动作失败。
- 失败不得重试 `move`，不得扩大角度，也不得绕过 ESP32 固件的遥测与限位策略。
- 唤醒动作失败不妨碍本地语音功能；记录稳定失败类别后继续正常语音会话。
- 动作适配器运行时，`VoiceLoop` 不启动普通 ASR 或下一次 KWS，因此保持半双工。
- 关闭、取消和异常均只关闭本适配器打开的文件描述符；不影响其他串口设备。

## 测试与验证证据

- Static check：检查 ESP32 现有命令协议、USB 设备路径策略、文件权限与代码格式。
- Code test：用伪串口传输测试命令顺序、响应解析、超时、`torque off` 兜底及
  语音循环集成；不得访问真实 USB、网络、麦克风或扬声器。
- Build：只运行已有 ESP32 固件和树莓派 Python 代码的编译/测试；不上传。
- Physical-hardware validation：单独得到授权后，首先观察 `status`，再执行一次
  `+5° -> -5° -> torque off`，记录 ESP32 串口回应和实际可见动作。不得把代码测试
  或历史台架结果表述为这一次验证。

## 非目标

- 不修改 ESP32 固件、不上传固件、不写死 `/dev/ttyACM0`。
- 不实现机械零位、软/硬限位标定、速度/加速度/jerk 控制、多关节动作、急停硬件
  或语音打断。
