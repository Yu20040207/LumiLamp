# LumiLamp 豆包流式语音识别 2.0 设计

## 目标

在 Raspberry Pi 上实现单次命令行语音识别流程：从已确认的 USB 麦克风采集音频，将音频实时发送至豆包流式语音识别模型 2.0，在终端显示增量识别结果，并在语句结束后输出最终文字。

本阶段不连接大模型对话或 TTS，不控制灯光、ESP32 或舵机。

## 已确认环境

- USB 麦克风 USB ID：`08bb:2902`，单声道、16-bit，原生支持 44.1/48 kHz。
- USB 扬声器 USB ID：`1b3f:2008`；本阶段不使用播放能力。
- 豆包资源 ID：`volc.seedasr.sauc.duration`。
- WebSocket 端点：`wss://openspeech.bytedance.com/api/v3/sauc/bigmodel_async`。
- 鉴权：兼容方式 `APP ID + Access Token`。
- 本地凭据：仓库根目录 `.env.voice`，权限 `600`，受 `.gitignore` 保护。

## 方案

使用现有 `arecord` 子进程读取原始 PCM，不引入 PortAudio 或 Python 音频绑定。ALSA `plughw` 负责将麦克风原生采样率转换为 16 kHz、单声道、signed 16-bit little-endian PCM。

程序每 20 ms 读取一个音频块，用现有 RMS 阈值逻辑进行语音起点和静音终点检测；同时聚合成 200 ms 网络包发送到豆包双向 WebSocket。检测到说话后的连续静音达到 800 ms，或本次录音达到 10 秒时，发送结束包并等待最终结果。

采用这一方案的原因：它能产生真实流式结果，复用当前录音与 VAD 代码，并且除了项目已经声明的 `websockets>=15,<16` 外不需要新增大型或系统级依赖。

## 组件与职责

### 配置

扩展语音配置加载，使 ASR 命令只要求以下字段：

- `DOUBAO_APP_ID`
- `DOUBAO_ACCESS_TOKEN`
- `DOUBAO_ASR_RESOURCE_ID`

ASR-only 命令不得因为尚未配置 Ark 或 TTS 而失败。凭据不得出现在对象表示、日志或异常文本中。

### 音频设备选择

设备发现优先使用稳定的 ALSA card 名称或 USB 标识，不写死易变化的数字卡号。首版允许通过 CLI 参数显式覆盖设备，默认选择与 `08bb:2902` 对应的 capture 设备；如果找不到或存在歧义，应停止并列出不含敏感信息的候选设备。

### 录音与 VAD

复用 `pcm_level` 和 `LevelConfig`。默认参数为：

- 输入格式：16 kHz、单声道、16-bit PCM；
- 音频读取块：20 ms；
- 网络发送包：200 ms；
- 连续静音结束时间：800 ms；
- 单次录音最长时间：10 秒。

说话前的静音不上传；首次超过起始阈值时开始当前语句。网络发送和响应接收必须并发，避免等待服务器响应时阻塞麦克风读取。

### ASR 2.0 WebSocket

将现有非流式端点替换为双向流式端点 `bigmodel_async`，并根据服务协议区分：

- 会话初始化请求；
- 普通音频包；
- 最终音频包；
- 增量识别结果；
- 最终识别结果；
- 服务端错误帧。

连接、首帧响应和最终结果都必须有明确超时。解析器返回结构化结果，至少包含文字和是否最终结果，避免 CLI 依赖原始二进制帧细节。

### CLI

提供一个仓库内可直接运行的 ASR 命令。执行后依次：

1. 加载 `.env.voice`；
2. 解析或发现麦克风设备；
3. 提示用户开始说话；
4. 实时显示增量文字；
5. 静音或超时后打印最终文字；
6. 关闭 WebSocket 和 `arecord` 子进程。

CLI 不自动启动，不作为开机服务，不保存录音文件。

## 错误处理与隐私

- 麦克风缺失、ALSA 启动失败、鉴权失败、网络超时、协议错误和空识别结果使用不同的错误信息与非零退出状态。
- 异常不得包含 Access Token、完整请求头或原始音频。
- PCM 只保存在内存中并发送给用户明确配置的豆包服务，不写入磁盘。
- 退出、异常或 Ctrl+C 时必须终止并等待 `arecord`，关闭 WebSocket，不遗留后台录音进程。

## 测试与验证

使用测试先行开发：

1. 为 ASR 2.0 初始化帧、音频帧和增量/最终结果解析编写协议测试；
2. 为 20 ms 音频聚合、VAD 起止和最长时限编写纯逻辑测试；
3. 为 CLI 的设备选择、配置错误、输出与清理行为编写隔离测试；
4. 运行全部 Python 单元测试，确保现有功能无回归；
5. 安装项目声明的 `websockets>=15,<16` 后进行真实网络连接；
6. 经用户现场确认后，用 USB 麦克风说一句短测试语句，分别报告设备录音、云端连接、增量结果和最终结果。

静态检查、自动化测试、真实网络服务验证和真实麦克风验证必须分别报告，不能互相替代。

## 非目标

- 大模型对话、TTS 播放和唤醒词整合；
- 持续后台监听或开机自动启动；
- 保存或上传录音文件；
- ESP32 通信、固件上传或舵机动作；
- 修改 GPIO、UART、供电、网络或 SSH 配置。
